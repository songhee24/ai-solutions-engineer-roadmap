# Раунд 8. Многостраничность вместо одного длинного листа

## Зачем

Дословно: «очень тяжело ориентироваться через один лист данных».

## Замер объяснил, что резать

| Что | Узлов в DOM |
|---|---|
| Вся страница | 6046 |
| **Раздел «Дорожная карта»** | **5543 — 92% всего веса** |
| Все остальные семь разделов вместе | 372 |
| Самый тяжёлый этап (трек математики) | 1258 |

Вывод, который поменял решение: **резать по разделам почти бесполезно** — карта и есть страница.
Настоящий выигрыш даёт только разбиение самой карты по этапам.

## Решение: клиентский роутер на хэше

Почему не отдельные HTML-файлы: шапку пришлось бы дублировать в восьми местах и держать
синхронно. Почему не History API: на GitHub Pages для глубоких ссылок нужен трюк с 404.

| Адрес | Что показывает |
|---|---|
| `#/` | Главная: цель, прогресс, срок, «Сейчас · Далее · Позже» |
| `#/roadmap` | Оглавление карты; при активном поиске — найденные темы |
| `#/stage/<id>` | Один этап целиком |
| `#/diagnostics`, `#/throughline`, `#/method`, `#/tutorial-hell`, `#/jobs` | Остальные разделы |

## Результат

| Страница | Узлов |
|---|---|
| Главная | **554** (было 6046) |
| Оглавление карты | 711 |
| Страница этапа | 700–1200 |

«Дорожная карта» стала оглавлением из 13 карточек. На странице этапа — стрелки «предыдущий /
следующий», так что по карте можно идти подряд. Заголовок там не сворачивается: тело и так
раскрыто.

## Детали, которые легко упустить

- **Старые ссылки `#track-math` продолжают работать** — роутер переводит их на страницу этапа.
- `renderStages` параметризован (`list`, `host`, `forceOpen`, `quiet`) и переиспользуется и на
  карте, и на странице этапа — новой функции рендера не понадобилось.
- Скролл-спай убран за ненадобностью: активный пункт теперь определяется маршрутом.
- Прогресс, `localStorage` и экспорт общие для всего сайта — не тронуты.

## Ошибка по ходу

При первой попытке правки индекс конца оказался раньше индекса начала, и хвост `app.js`
продублировался — 12 функций в двух экземплярах. Замечено проверкой на дубликаты, файл откачен
к последнему коммиту и правка переделана с точными границами. Урок: после структурной правки
всегда проверять `grep "^  function " | sort | uniq -d`.

## Чем проверяли

Тесты переписаны под маршруты: 60 проверок вместо прежних 61, включая неизвестный маршрут
(падает на главную) и старые якоря.
