# CLAUDE.md — ai-solutions-engineer-roadmap

Статический сайт-роадмап («одна база, четыре финала»), русскоязычный.

**Две части, и они живут по разным правилам:**

| Часть | Что это | Правила |
|---|---|---|
| **Карта** (корень) | `index.html` → `roadmap-data.js` + `app.js` + `styles.css` | Без фреймворков, без сборки, без зависимостей. Открывается как простые файлы |
| **Прикидка по дням** (`docs/plan.html`) | Калькулятор до старта: считает дни от даты читателя, но **ничего не сохраняет**. Общее ядро — `shared/schedule.mjs` | Отдельная страница, ES-модуль без сборки |
| **Планнер** (`planner-src/` → `planner/`) | Три экрана: «Сегодня» (галочки), «Календарь» (пропуски), «Карта знаний»; шаблоны дня и свои темы — секциями в «Настройках» | Svelte 5 + Vite. Исключение от 2026-08-31, см. ниже |

Общее ядро планирования — `shared/schedule.mjs` (чистые функции, Node и браузер), генератор
расписания — `scripts/build-schedule.mjs` → `docs/first-weeks.md`.

Локальный запуск карты: `python3 -m http.server 8765`. Планнер: `npm --prefix planner-src run dev`
(или `npm run build` и открыть `/planner/` тем же сервером). Тесты ядра: `node --test
"planner-src/test/**/*.test.mjs"`.

## Проверки — три слоя, каждый своим инструментом

| Что | Где | Как запустить | Зависимости |
|---|---|---|---|
| **Данные карты** | `test/roadmap-data.test.mjs` | `node --test "test/**/*.test.mjs"` | нет, голый Node |
| **Ядро планнера** | `planner-src/test/*.test.mjs` | `node --test "planner-src/test/**/*.test.mjs"` | нет |
| **Роутер и разметка карты** | `planner-src/test/map-ui.test.mjs` | там же | jsdom |
| **Живые страницы** | `scripts/check-site.mjs` | см. шапку файла | свой headless-Chrome |

⚠ **jsdom-тесты карты лежат в `planner-src`, а не в корне, намеренно**: корень обязан оставаться
без npm, а `planner-src` — единственное место, где сборка разрешена. Проверки данных зависимостей
не имеют и живут в корне.

⚠ В jsdom обязательно **ждать событие `load`** перед исполнением `app.js`: сразу после конструктора
`document.readyState === "loading"`, и app.js уходит ждать `DOMContentLoaded` — `init()` не
запускается, ничего не рисуется, тесты падают загадочно.

⚠ `scripts/check-site.mjs` и `check-links.mjs` **отключают кеш Chrome**. Без этого проверка
показывает прошлый прогон, и только что исправленное «остаётся» сломанным.

Деплой: push в `main` публикует **корень репо** на GitHub Pages
(`.github/workflows/deploy-pages.yml`); планнер собирается там же шагом `npm ci && npm run build`.
**Собранный `planner/` не коммитится** (он в `.gitignore`): закоммиченная сборка молча
расходилась бы с исходником, а упавшая сборка в CI видна сразу и предыдущий деплой остаётся живым.

## Правила кода (2026-08-29, проектный слой поверх глобального Code yardstick)
Глобальный yardstick действует (понятность, никакого оверинжиниринга). Специфика проекта:
- ⛔ **Сайт-карта: никогда не заводить npm/бандлер/фреймворк/модули.** `index.html`,
  `roadmap-data.js`, `app.js`, `styles.css` обязаны открываться как простые файлы; «улучшение»
  карты через сборку — это регресс. Правило действует и для любого другого проекта.
  <br>**Единственное исключение (2026-08-31, решение Akara): планнер учёбы в `planner-src/`** —
  отдельное приложение на Svelte 5 + Vite, собирается в `planner/`. Причина: планнеру нужны
  дневная сетка, шаблоны дня, свои темы и графики прогресса — на голом DOM это выросло бы в
  вторую `app.js`, а карта при этом должна остаться нетронутой. Границы исключения жёсткие:
  сборка касается **только** `planner-src/`; `index.html`/`app.js`/`styles.css`/`roadmap-data.js`
  не меняются и продолжают работать без Node. `shared/schedule.mjs` — общее ядро планирования,
  обычный ES-модуль: его импортирует и генератор в Node, и отдельная страница `docs/plan.html`
  через `<script type="module">`. Сборки для этого не нужно, браузеры понимают модули сами;
  на карту это никак не влияет.
  <br><small>Прежняя формулировка (2026-08-29, до появления планнера): «Никогда не заводить
  npm/бандлер/фреймворк/модули. Репо обязан открываться как простые файлы.» — оставлена как
  история решения.</small>
- **Жёсткое разделение:** контент ТОЛЬКО в `roadmap-data.js` (шапка файла: «правьте только этот
  файл»; схема stage/topic/resource задокументирована там же комментарием), UI ТОЛЬКО в `app.js`
  (hash-роутер `#/`, `#/stage/<id>`, …). Копи-текст в `app.js`/`index.html` не хардкодить.
- **Стиль `app.js` — classic-script IIFE** (`"use strict"`, `var`/`function`, без import/export) —
  новый код соответствует существующему, не «модернизировать» точечно. В `planner-src/` и
  `shared/`/`scripts/` — наоборот, обычные ES-модули; смешивать стили внутри одного файла нельзя.
- **Каждый добавленный URL ресурса реально открыт** и получает дату в поле `checked` — карта
  доверия живёт этим. ⚠ Khan Academy проверять только реальным браузером: curl/фетч отдаёт 200
  даже на несуществующий слаг.
- **`localStorage` версионирован, и ключей ДВА, независимых**: карта живёт в `"asr:v1"`
  (`app.js`), планнер — в `"asr:planner:v1"` (`planner-src/src/lib/store.svelte.js`). Очистка
  одного не должна ломать второй. Менять форму состояния только с бампом `v` и обратной
  терпимостью при разборе (defensive parse есть в обоих — сохранять).
- **Планнер хранит журнал, а не календарь.** В `log` лежит «что и когда закрыто»; план на день
  каждый раз выводится заново из непройденного (`lib/progress.js` → `shared/schedule.mjs`).
  Отсюда бесплатно берётся обещанное поведение: пропущенный день ничего не теряет, он лишь
  сдвигает финиш. **Не заводить хранимый календарь** — он сломает ровно это свойство.
- **A11y-конвенции сохранять**: skip-link, `aria-pressed` на тогглах, `visually-hidden` подписи,
  `role="group"`. UI-язык русский, `lang="ru"`.
- **Корень = продакшен**: мусорные/черновые файлы в корень не коммитить; `.nojekyll` не удалять.
- ⚠ **`design/` — черновики, а не приложение.** 02.09.2026 макет приняли за рабочий планнер и
  поверили выдуманным числам. Поэтому: на каждом файле в `design/` обязана быть `.draft-bar`
  со ссылкой на `../planner/`, вкладки макетов намеренно НЕ повторяют пилюли планнера, а из
  верхней навигации макеты убраны в подвал. Новый макет — сразу с полосой.
- Планы раундов — датированные файлы в `.claude/plans/` (12 штук; свод —
  `ai-solutions-engineer-roadmap.md`).
